Snapshot-gated RTL rewrite: optimise, expand, and trim

A CHIA loop that freezes an SVApshot contract once, then scores port-frozen LLM rewrites with Yosys PPA and VC Formal reprove.
Draft · CHIA × SVApshot

Yosys cells / LTP — not GE or Watts

Claim

One frozen SVA snapshot is enough to run three rewrite modes on the same DUT. Both better PPA with a passing snapshot and a failing snapshot on the new RTL are headline results — not only the first.

Optimise Same ports and function. Retry toward a passing snapshot. Optional axis: top vs hierarchy.
Expand Keep every current result. Add one capability. Pass or fail is evidence.
Trim Same ports. Keep the essential path. The old contract often dies — that is the measurement.

Method

Stage DUT (+ match_instance parent defaults) → VC Formal elaborate (hard gate) → Yosys baseline → SVApshot generate/freeze → for each mode: Gemini rewrite → retain → reprove → Yosys candidate → score. Observational EQY LEC if the snapshot passed. The only back-edge is reprove → rewrite on optimise.

Optimise: top vs hierarchy

On fpnew_top, top may rewrite only fpnew_top.sv. Hierarchy may rewrite children (opgroup, FMA, DivSqrt). Same snapshot, different blast radius.

How to read a cell

  • Green Δ + passing snap — snapshot-pass PPA wins: div_unit optimise (30/30) and trim (13/13).
  • Passing snap, worse or flat PPA — the rewrite was legal and useless for area/delay (ptw optimise, div_unit expand).
  • Red snapshot — new RTL left the contract. Expected on trim/expand; a problem if optimise wanted a win.

EQY LEC is observational. Functional gold for the graph is the snapshot.
